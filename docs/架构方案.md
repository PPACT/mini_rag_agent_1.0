# 架构方案（RAG-Agent 企业知识库）

> 本文档汇总当前项目的完整设计：定位、选型、分层、数据模型、核心链路、扩展点与已知边界。
> 姊妹文档：`docs/开发记录.md`（开发过程与踩坑）、`改进计划.md`（本地，改进追踪）。

---

## 1. 项目定位

面向 B 端企业内部的知识库问答系统。用户上传文档（PDF/Word/PPT），用自然语言提问，系统检索知识库、按需调用业务系统工具、生成带引用溯源的答案。

**设计目标**：本地免费部署可跑 + 企业级扩展口子预留 + 后期平滑迁移（Milvus / 云 Embedding / 云 LLM）。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| Web | FastAPI + Uvicorn | 异步、轻量、类型友好 |
| 向量存储 | PostgreSQL 17 + pgvector | 单库事务、免运维第二套 DB、与业务数据同库 |
| 缓存 / 队列 | Redis + Arq | 缓存问答结果 + 异步文档处理，轻量 |
| Embedding | 本地 Ollama `bge-m3`（1024 维） | 免费、中文好、本地不出网、GPU 加速 |
| LLM | DeepSeek 云 API | 测试成本低、省显存、function-calling 可靠 |
| Agent 编排 | LangGraph（`langchain.agents.create_agent`） | 标准 ReAct 图，可插工具 |
| MCP 工具 | FastMCP（stdio） | 走真协议，上线替换真实服务只改连接 |
| 文档解析 | pdfplumber / python-docx / python-pptx | 免费、纯 Python |

## 3. 架构分层

```
API 层        api/          upload_api, chat_api
鉴权层        auth/         token → 用户身份（部门 + 密级）
编排层        agent/        graph_builder(LangGraph), mcp_mock_server(FastMCP), mcp_client_wrapper
检索层        rag/          retriever（向量检索 + 权限过滤）
抽象层        embedding/    BaseEmbedding → OllamaEmbedding / CloudEmbedding(占位)
              vector_store/ VectorStore → PgVectorStore / MilvusStore(桩) + AccessFilter
数据层        db/           asyncpg 连接池 + transaction()；Alembic 迁移
缓存/任务     cache/ tasks/ Redis 缓存；Arq worker + document_task
解析层        document_parser/  loader(多格式) + semantic_splitter(结构优先切块)
横切          config/ schemas/ observability/
```

**核心设计原则**：各层通过抽象接口通信，配置驱动实现切换（`VECTOR_STORE` 开关），业务代码不感知底层引擎。

## 4. 数据模型

**documents（主表）**

| 字段 | 说明 |
|---|---|
| id | UUID 主键 |
| filename | 落盘文件名 |
| status | `pending` → `processing` → `completed` / `failed`（含 `deleted`） |
| version | 版本号，更新时 +1 |
| chunk_count / error | 切块数 / 失败原因 |
| created_at / updated_at | 时间戳 |
| is_deleted | 软删标记 |

**chunks（向量表）**

| 字段 | 说明 |
|---|---|
| id / document_id | 主键 / 外键（ON DELETE CASCADE） |
| chunk_index / document_version | 块序号 / 所属文档版本 |
| content / embedding | 文本 / `vector(1024)` |
| department / secret_level | **权限元数据** |
| source_file | 来源文件名 |
| start_offset / end_offset / title | **溯源定位**（字符偏移 + 章节标题） |
| is_deprecated | **废弃标记**（疑似过期，检索过滤） |
| create_time / updated_at | 时间戳 |

**索引**：HNSW 向量索引、`document_id`、`(department, secret_level)`、`is_deprecated`、`is_deleted`、`updated_at`。

**一致性规则**：增删改同事务；更新 = 同事务删旧 chunk + 插新 + version+1；删除 = 软删；检索恒带 `is_deleted=false AND is_deprecated=false`。

## 5. 核心链路

**① 文档上传（异步，不阻塞）**
```
POST /documents/upload (file + secret_level + 可选 document_id)
  → 鉴权（token → 部门/密级）；校验密级不超过上传者
  → 流式写盘（50MB 上限）
  → INSERT/UPDATE documents(status=pending, version+1)
  → Arq 入队 → 返回 document_id
Worker: 解析 → 结构优先切块 → bge-m3 批量嵌入 → 同事务替换 chunk → status=completed → 作废缓存
```

**② RAG 问答（同步）**
```
POST /chat (question)
  → 鉴权（部门/密级取自 token，不信任客户端）
  → Redis 缓存检查（key 含 question+department+secret_level+top_k）
  → query 向量化 → pgvector 检索 + 权限过滤（department ANY + secret_level <=）
  → 拼上下文 → LangGraph Agent（LLM 按需调 MCP 工具）→ 生成答案
  → 写缓存 → 返回 {answer, sources[]}
```

**③ 鉴权**
`Authorization: Bearer <token>` → `DEMO_USERS` 映射到（姓名/部门/密级）。演示用静态 token，真实环境替换为 JWT/SSO。

## 6. 扩展点（后期迁移口子）

| 扩展点 | 现状 | 切换方式 |
|---|---|---|
| LLM | DeepSeek | 改 `litellm_config.yaml` / `.env` |
| Embedding | 本地 bge-m3 | 实现 `CloudEmbedding`，改工厂 |
| 向量库 | pgvector | 实现 `MilvusStore`，改 `VECTOR_STORE` |
| 任务队列 | Arq | 状态字段已预留，换 Celery 不改表 |
| 权限 | 元数据过滤 | 开 PG RLS，字段已建好 |
| 文档解析 | pdfplumber 等 | 换 LlamaParse，改 loader |
| 观测 | logging 占位 | 接 OTel Exporter |

## 7. 当前能力清单（已验证）

**功能**：文档上传→异步解析→切块→向量化→入库；RAG 问答 + 引用溯源 + 缓存；MCP 工具调用；文档更新（版本+1 替换）；多格式解析；结构优先切块。

**工程**：接口鉴权 + 权限隔离（已实测跨部门看不到）；上传限流；LLM 超时重试；Redis 内存限制；依赖锁版本；Alembic 迁移（0001/0002）；9 个单元测试；密钥/隐私脱敏。

## 8. 已知边界（未实现）

无多轮对话、无流式输出、无 rerank、无 query 改写、无 RAG 评测、无前端、无真实监控告警、单 worker 无水平扩展、静态 token 鉴权、纯文本解析（无 OCR）。
